Roc GUI is a platform for writing native desktop applications in Roc, rendered by
[GPUI](https://www.gpui.rs/). The goal is to make it easy to build great desktop experiences. There is no virtual
DOM, no diffing, and no component lifecycle to learn - just pure `init` and `render`.

When you build an app using this platform, `roc build`, there is also a test harness included for behaviour testing
using specifications written using S-expressions. This can make it easier to "test what you fly" with both a headless mode 
and also scripting inputs just like a human - the application has no concept that it is being driven in a test harness.

This is the first release. It is still very early and I expect a lot to change. My focus has been 
on putting everything together, and laying the foundations to build and iterate from. Most of the work
has been wrangling CI, packaging gpui and linker inputs, and then testing and ironing out bugs cross-platform.

## Using this release

Use the platform URL in the application header.

```roc
app [State, main] { pf: platform "{{BUNDLE_URL}}", roc: "{{COMPILER}}" }

import pf.Elem
import pf.Program

State : { clicks : U64 }

render : State -> Elem(State)
render = |state| Elem.col(
	{ label: "Counter", gap: 8, padding: 12 },
	[
		Elem.text("Clicked ${state.clicks.to_str()} times"),
		Elem.button({ caption: "Click me", label: "Click me", on_press: |s, _| Action.update({ clicks: s.clicks + 1 }) }),
	],
)

main : Program(State)
main = Program.run({ init: { clicks: 0 }, render })
```

```sh
roc main.roc
```

Note that for now **`--opt=dev` is required.** The default LLVM backend in the pinned compiler has a
code-generation defect that produces incorrect initial state and reference-count failures at
runtime. Later compiler releases are expected to fix this but I haven't had time to test it yet.

## Compiler

This release is pinned to Roc `{{COMPILER}}`. The platform declares that pin, so a
consuming application resolves the same compiler rather than whatever is newest. Later
nightlies are not supported by this release and are known to break it.

## Targets

| Target | Platform |
| --- | --- |
| `x64glibc` | Linux x86-64 (glibc) |
| `arm64mac` | macOS Apple silicon |
| `x64mingw` | Windows x86-64 |

Each target is tested by the release pipeline against the exact bundled bytes below — every
example and benchmark is rebuilt from the published bundle and every specification is run,
on that operating system, before the release is created.

Linux needs `libfreetype6`, `libxkbcommon0` and `libxkbcommon-x11-0` present at runtime.

## Examples

Fifteen worked examples ship in the examples archive, from a two-counter demo to an HTTP
client, a read-only SQLite browser, a terminal workspace, an image library, a `.wav` player,
a system monitor and a retained-canvas animation editor. Each carries its own executable
test specifications beside it.

### Verifying what you downloaded

Every asset carries a GitHub build attestation binding it to the workflow that produced it:

```sh
gh attestation verify {{BUNDLE_NAME}} --repo lukewilliamboswell/roc-gui
```

`release-manifest.json` records the digest and size of the bundle, plus the exact release
identity of every host archive and external link input that went into it.
