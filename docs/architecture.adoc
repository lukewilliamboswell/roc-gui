= How Roc GUI works

This chapter is the map of roc-gui for advanced users and contributors. It
explains the path from application state to pixels, the path from input back to
state, and the replacement model that joins them. You do not need to know GPUI
internals to follow it.

The crucial detail is that roc-gui does not diff two virtual trees. Explicit
component boundaries select the scope of an update. Within that scope, keyed
memoized components can retain their complete mounted subtrees; the remainder
is rendered and lowered into fresh nodes. Native controls retain their
interaction state according to a separate, scoped identity contract.

== The model in one page

roc-gui has three representations of a UI:

`Elem` value:: A short-lived Roc description produced by a renderer. It carries
text, layout, buttons, checkboxes, controlled text inputs, handlers, and
explicit render boundaries.
Mounted graph:: The host's canonical, validated tree of native nodes. It is the
source of truth shared by the interactive window and semantic specifications.
GPUI entities:: Retained native views materialised from mounted nodes. GPUI uses
them to perform its rendering-system work and deliver input.

The application never mutates the mounted graph or GPUI entities directly. It
returns an `Action`; the platform turns that action into exactly one patch; and
the host applies it through the same graph implementation in every GUI host and
the semantic runner.

Resource security has a separate boundary from graph ownership. The application
process is confined by the operating system; trusted broker services own
protected selection, persistent identity, and revocation. Opaque Roc handles
cross that boundary, while raw paths and platform persistence mechanics do not. The
Resource access chapter describes that boundary.

== From state to pixels

=== The application renders a value

`Gui.run` supplies pure initial state, a pure renderer, and optional
resizable-window metadata. Calling the renderer produces an immutable
`Gui.Elem(State)` description. Composition stays in Roc: styled and semantically
named `Gui.row`, `Gui.col`, `Gui.panel`, `Gui.text`, `Gui.button`, and
named `Gui.scroll` regions build the tree. `Gui.translate` introduces a local
boundary with ordinary state adapters; `Gui.translate_with` and
`Gui.try_translate` add explicit keys and optional policies. They are pure
descriptors, with no setup-time registration or function-identity comparison.
A translation adds no layout surface.

An `Elem` is not a long-lived widget object, and rendering one does not draw
pixels. It is an intermediate value consumed immediately by platform lowering.
The application renderer runs initially and after an updating event; it does
not run for every display frame.

=== The platform lowers the description

The platform lowers the `Elem` description into native nodes with host-issued
identities. The result is staged separately from the visible graph so it can be
validated as a complete change before commit.

Framework-owned element-descriptor traversal, native-node lowering, and boundary
retirement use explicit work stacks. Enter and finish items preserve child
order, native scopes, delegation ownership, and measurement boundaries while
keeping unfinished traversal in managed memory. Finish items hold shallow
container properties or owner metadata, allowing processed descriptions to be
released incrementally. Native entity materialization and retirement use the
same iterative traversal principle.

Traversal and callback execution have distinct depth contracts. Descriptor
mapping suspends container reconstruction in heap work items; render adapters
compose typed state projections and result adaptation. Verify these owners
independently, including both a deeply nested structural tree and a chain of
translation boundaries. Native layout is a third execution path with its own
verification requirements.

Typed state adapters use a fixed-result continuation protocol. A renderer,
projection, memo predicate, or action adapter returns a work item instead of
calling an arbitrarily deep adapter chain to completion. Both descent into a
child and ascent through parent setters suspend before invoking the next
continuation. Adjacent states can have different types; their values remain in
typed Roc closure captures. The work executor has no application-state payload
and the host does not decode one.

Protocol builders and continuations are pure. Effects execute in deferred work
items, including the terminal item that commits the transition or delivers a
task resolver. One iterative executor drives those items. Configured getters
and setters have distinct work tags, so their invocation counts measure actual
projection callbacks rather than the number of adapter wrappers. A missing
projection short-circuits its remaining chain, and a rejected setter discards
the candidate before delegation handling or task launch.

During the same walk, the platform builds event routes and records each
boundary's instance, renderer, native root, parent, and route revision. A route
connects a native event identity to a Roc handler and its owning boundary.
Routes and boundaries live in indexed registries; each boundary owns lists of
its direct routes and child boundaries, so replacing it need not filter all
routes in the application.

Application keys retain all 256 SHA-256 digest bits. String keys hash a byte
`0` followed by UTF-8 bytes; numeric keys hash a byte `1` followed by eight
little-endian bytes. This separates numeric and string identities without a
short-name limit or truncation. String literals use `Gui.Key.from_quote` at
compilation; computed strings use `Gui.Key.from_str` at runtime.

Lowering resolves a keyed boundary using its surviving owner, native-container
scope, and full SHA-256 key digest. The host validates the 32-byte digest and
assigns a separate, monotonically increasing mounted-instance ID. A matching
key preserves the lifetime across parent rebuilding and reordering within that
scope. Duplicate keys in one scope are rejected. Unkeyed translations allocate
fresh lifetimes when reconstructed by their parent; a local update preserves
its own boundary. Key names and digests never enter observatory captures.

A keyed column carries a persistent ordered sequence and its exact
one-generation journal into lowering. The Roc owner applies that journal to its
persistent keyed-instance metadata, then publishes one atomic mounted-graph
transaction and one native-container transaction. Inserts and sets render the
affected item; moves retain its component and native identity; removals retire
that identity and its routes. If the mounted owner has an older revision, the
column lazily enumerates its complete ordered snapshot and reconciles surviving
keys. Any rejected operation publishes neither graph nor native state. The Roc
runtime, graph, native container, and GPUI frame each record only the work they
own, so a bounded graph edit is not used as evidence for unmeasured layout or
paint.

A keyed boundary can opt into memoization. A matching instance with the same
policy and valid snapshot compares the saved input with its input in latest
state. A hit retains the complete marker subtree, routes, and nested boundaries
without rendering or lowering its contents. A miss builds a fresh marker and
contents, giving nested keyed translations the same opportunity to survive.
Enabling or disabling memoization rebuilds and resets the cache while retaining
the instance and its tasks. Unmemoized boundaries keep no input snapshot.

Lowering ends with exactly one `Mount`, `Replace`, or `NoChange` commit. Staging
alone cannot modify the visible graph.

=== The host validates and commits

The host validates a staged tree before accepting it. References and ownership
must be internally consistent, the result must describe one valid tree, and a
replacement target must still belong to the mounted graph. Retained roots must
be live component markers from the subtree being replaced. They form a disjoint
forest: none can be retained twice, shared with another owner, or made its own
ancestor. Validation visits fresh nodes and the retained frontier, using saved
subtree summaries for whole-graph constraints instead of traversing retained
contents.

The canonical `MountedGraph` then applies the patch:

* `Mount` installs the first root.
* `NoChange` leaves the graph untouched, including when an accepted state change
  needs no new UI after memo comparison.
* `Replace` atomically substitutes a staged tree containing fresh nodes and
  explicitly retained subtrees for a mounted subtree.

The graph decision is the transaction's acceptance boundary. Only after it
succeeds does the host publish the successor session, component registry
changes, and submitted jobs. Rejection releases staged ownership without
publishing a new dispatcher or starting a task against an uncommitted tree.

Node IDs and component mount tokens are distinct and never reused. A node ID
removed by replacement is stale. A component's mount token survives a matching
rerender, but retirement ends its lifetime even if the same key is mounted
again later.

=== The host materialises GPUI views

Ordinary newly mounted graph nodes become GPUI `Entity<NodeView>` values. Rows
and columns become flex containers, panels become styled surfaces, dialogs
become centred modal layers with input-blocking scrims, text becomes a text
child, and enabled action buttons add focus, keyboard, and pointer
listeners. A boundary marker materialises as a transparent single-child view,
not a synthetic row, column, or styled surface. Retained marker subtrees retain
their native views without rebinding their unchanged content. Disabled action
buttons add no event listener or tab stop. Text input
entities retain native focus, caret, selection, and IME preedit state while
committed values cross the same controlled Roc replacement boundary. IME
preedit remains transient in the editor and dispatches one change when the
composition commits. A virtual list is the deliberate exception: its complete
keyed item subtrees remain in the canonical graph, but GPUI's
viewport callback creates entities only for intersecting fixed-height rows and
recycles entities that leave the range. GPUI asks for one row to measure and
then for the rows it shows, so a list's frame is settled once, after GPUI has
drawn it: rows that left the view are recycled, the measured row is kept, and
the frame's materialisation is recorded. The host connects the new native
subtree to retained entities around its boundary and releases replaced views.

A list of rows produced on demand goes further: the canonical graph holds only
a window of its rows. The list lowers inside its own transparent render
boundary, and lowering asks the host which rows to build, because the host owns
the viewport. The host keeps that viewport per boundary instance, since the list
node is replaced whenever its window moves. It places the rows the viewport
shows and one viewport either side, applies a scroll request once per serial,
and, before GPUI has drawn the list, takes the viewport to be as tall as the
window. GPUI's callback draws the list's full length and holds the place of a
row that is not mounted. When a settled frame shows rows within half a viewport
of the mounted edge, or shows a new range the application asked to hear of, the
host dispatches the list's own route. That turn renders the list boundary again
against unchanged state, which invalidates no ancestor's memo snapshot, and the
new window replaces the old one in one ordinary patch. An action a row raises
passes through the transparent boundary to the list's owner.

The host enables GPUI's native view cache for non-root button leaves, rows,
columns, and panels whose pixel width and height equal their minimum and
maximum dimensions and whose `grow` is false. Transparent single-child
boundary chains share that eligibility. Baseline-aligned subtrees use ordinary
layout so that descendant content supplies the correct alignment baseline.

An unchanged eligible container reuses its subtree without constructing its
children's native view elements. A changed descendant invalidates the ancestor
path; rebuilding an ancestor permits independently unchanged children to reuse
their caches. Changed geometry, clipping, inherited text style, and explicit
window refresh invalidate affected cached content. Reused subtree frame ranges
are relocated when the frame completes, preserving later child updates and
native event routing.

Intrinsic and flexible dimensions follow ordinary GPUI layout. Changing a
retained node's dimensions or baseline context reevaluates cache eligibility.
This cache is independent of Roc boundary memoization. Rebuilding containers
still visits their immediate children, and GPUI scene replay and native input
dispatch have their own scaling costs.

A node ID identifies a node, not a control. Because it is never reused, a patch
that rebuilds a subtree gives the same control a new ID, and keying the GPUI
element by it would hand that control a new element on every patch and discard
the element state GPUI holds — the pending mouse-down that pairs a press with a
release, the scroll offset, the focus. The host therefore keys each element by
the node's *element identity*: the path of sibling keys from the mounted root,
each key the node's own semantic name where it has one and its position among
its siblings where it has not, with repeated sibling names separated by
occurrence. A staged node claims back the view of a retired node with the same
identity and the same kind. Component instance tokens also scope these paths:
two instances may contain controls with the same local name without sharing
native editor or interaction state. Within an unchanged structural scope, a
control can survive repeated rerenders under a held press. Nothing of the retired
node's content survives with it: handlers are rebuilt from the staged node, so a
click still routes to the live node ID, and a control whose name changed or that
left the tree has a different identity, gets a different element, and drops the
press rather than having it misrouted to whatever took its place.

Keys do not promise arbitrary reparenting. Moving a component within its keyed
parent scope preserves its instance; changing an ancestor's kind, name, or
structural path remounts it. Removing and recreating the same key also remounts
it. Native focus, caret, IME preedit, scroll offsets, and pending presses belong
to these scoped lifetimes, not to a globally reusable application key. A virtual
row leaving the materialised viewport does not remove its canonical component
instance or revoke its tasks. A row produced on demand that leaves the mounted
window leaves the graph, and its components retire with it like any removed
subtree; state that must outlive the row belongs to the list's owner.

An ordinary patch keeps focus on the control that had it, by its stable role
and semantic name, even where the node carrying that control is a new one. A
control that leaves the graph entirely hands focus to whatever now occupies its
place in the tab order — for a deleted row, the row that followed it, and for
the last control, the new last one. Focus is dropped only when a graph has
nothing focusable left, because then there is nowhere for it to go.

While a dialog is mounted, controls outside its graph subtree do not install
pointer listeners or tab stops. The runtime focuses the first enabled dialog
control, routes Escape to the dialog node, and restores the opener by its stable
role and semantic name after the dialog leaves the graph.

The host notifies GPUI of the changed entity. GPUI owns subsequent rendering,
layout, prepaint, paint, and presentation. roc-gui does not calculate geometry
or issue GPU commands in Roc, and one application event does not necessarily
correspond to one presented frame.

[mermaid]

    P-->>H: return from Roc turn

The session is one-shot state: one boxed dispatcher owns the state, routes, and
boundaries valid for the mounted graph. Events and worker completions enter
that same dispatcher through a typed Roc message, and each accepted turn
installs its successor. The ABI erases boxed callables, not an unboxed generic
state union. There are no separate installed event and completion closures
forcing duplicate captures of the root state.

Handlers receive the latest state rather than a render-time snapshot. The host
checks that native event IDs remain live; Roc also checks the owning instance
and its route revision. Rebuilding a live component advances its revision, so a
callback from an old route cannot address a new handler in that same instance.

== Boundaries determine update scope

`Gui.translate(render, get, set)` relates child state to parent state and
creates a rendering, delegation, and task-ownership boundary. The application
renderer is the root boundary. `Gui.translate_with` supplies a key and optional
policies; `Gui.try_translate` uses fallible getters and setters for removable
state. Adapters operate on state rather than decoding keys. The `lift` method only
adapts a prebuilt element's handlers: it adds no lifetime or boundary and does
not consume delegation.

`Gui.update` commits through the adapters and renders only the originating
boundary. It neither renders nor compares unrelated siblings. Parent summaries
respond through explicit delegation or composition within one render boundary.
The platform does not infer dependencies by tracking state reads.

`Gui.delegate(next_child)` constructs a candidate parent and passes it to the
nearest translation's `on_delegate` callback. Its parent action accepts,
revises, vetoes, starts parent-owned work, or delegates further. `Gui.none`
vetoes the entire candidate. Delegation reaching the root becomes a root
update; the default callback accepts with `Gui.update`.

A key promises a stable logical component and state projection for its mounted
lifetime. Rebinding either requires a different key. Removal, a changed key or
scope, and owner remount all end a lifetime. Missing projections cannot recreate
deleted state, and emitting a boundary with a missing projection is an
application error. Parent-owned data survives reconstruction unless changed by
an action.

=== Memoization is an explicit behavioral contract

Memoization is opt-in through `memo: Some(compare)` on a keyed translation.
Ordinary translations require no equality and retain no comparison snapshot.
Comparison is performed only at boundaries reached by rendering. The input
must include all variable rendering and captured-handler dependencies,
including labels, layout choices, and parent properties. Renderer captures and
comparators remain semantically stable for the keyed lifetime; no function or
pointer equality establishes identity.

Returning `True` promises that keeping the old subtree and its handlers is
observationally equivalent to rebuilding with the new input. Ordinary equality
is suitable only when it satisfies that promise. Custom equality can omit a
relevant field, and floating-point equality can equate positive and negative
zero even when a renderer distinguishes them. A false negative costs work; a
false positive violates the application contract. The availability of equality does not establish this behavioral law. Deterministic
floating-point calculations do not imply representation-sensitive equality:
inputs whose signed zero matters need an exact wrapper or a custom comparator.
No hashing or comparison of renderer functions is used.

The saved snapshot belongs to the mounted output. A local descendant update
invalidates every strict ancestor's memo snapshot, even when those ancestors
are not rendered. That prevents an ancestor's old `A` snapshot from incorrectly
skipping after descendants changed it through `A -> B -> A`.

Typed child snapshots are erased into boxed comparison closures over the root
state, not stored in an existential record field. Retaining such snapshots can
increase reference counts and prevent Roc's in-place updates. The single
session avoids an unnecessary duplicate root capture; it does not guarantee
unique ownership of lists, strings, resources, or indexed registry nodes.

== Asynchronous action turns

A `Gui.task` proposes its pending state and a boxed worker. After graph
acceptance, the host queues the worker on the native pool. The worker runs its
continuations and hands a boxed reducer to the host completion slot. The UI
thread delivers that reducer through
the latest session, applies its action with the same ownership and memoization
rules as an event, and commits one graph decision.

A task belongs to the boundary instance that accepts the task action. A
matching ancestor rerender or keyed reorder preserves that owner. Semantic
removal retires it permanently. Before invoking a completion or any captured
child getter, the session verifies that the owner and its ancestor projections
still exist. A removed owner's completion is discarded; it never recreates
child state and never falls back to the root. To outlive a child, work must be
started by a surviving ancestor, including through `on_delegate`.

Discarding a completion releases its result and captured resources through
normal reference counting. It revokes delivery, not arbitrary running effects:
a blocked worker can still own a resource until its operation finishes or an
explicit capability cancellation wakes it. Request identities in application
state handle superseded work within one live instance; component lifetime does
not imply a latest-request-wins policy. Roc values cross threads only as owned
erased callables; generic state and actions remain boxed across the ABI.

Periodic subscriptions use the same route. A timer has at most one waiting
`Gui.TimerHandle` `next!` task. Its wait parks on a worker and returns a normal boxed
reducer; the UI thread applies that reducer through the installed session.
Cancellation wakes the waiter, and cadence advances from the completion of the
preceding pull, so a slow consumer cannot create an unbounded event backlog.

HTTP requests also use `Gui.task` and the canonical worker/completion route.
An opaque `Box(U64)` client names a host registry entry for one explicitly
granted origin. The initial URL and every redirect retain its scheme, host, and
effective port.
Application-data file operations use that route as well. Roc retains only an
opaque typed read-write directory handle; the host confines flat child names to
the granted application root, bounds values, and commits each atomic write by
synchronising a private temporary file before an in-root rename. Application
request identities decide whether a completion is still current on the UI
thread.
Clipboard observation follows the same capability and task boundary. GPUI's UI
context owns operating-system reads and writes; the host publishes only the
latest bounded text and a monotonic sequence to capability-checked worker
calls. The application timer supplies backpressure and cancellation. Neither
the shared snapshot nor clipboard values are observatory fields.
The host applies explicit scheme, timeout, redirect, header, request-body, and
response-body limits before returning an owned reducer to the UI thread. It
buffers one bounded byte response rather than exposing a streaming callback.
Applications suppress obsolete completions by comparing their request identity
with latest state. URLs, headers, bodies, and response text never enter host
captures or deterministic diagnostics.

Directory, HTTP, and timer handles are typed nominal wrappers over `Box(U64)`.
Each token names a host registry entry containing a `cap_std::fs::Dir`; final box deallocation
removes that entry. The phantom resource kind leaves room for other handle
families without allowing their types to be confused. The trusted resource
broker creates a grant only for the selected project. Listing and child
acquisition operate relative to the stored handle, and child acquisition uses
the no-follow operation from `cap-fs-ext`.

== There is no node-level diff

roc-gui compares declared component inputs and matches explicit component keys;
it does not diff arbitrary old and new `Elem` descriptions or mutate equivalent
ordinary nodes in place. Fresh output outside retained component subtrees gets
fresh node IDs, even if its text and position are unchanged.

This makes the costs and semantics direct:

* the boundary structure exposes replacement and invalidation scope;
* key scope and memo equivalence are explicit application contracts;
* removed routes and node IDs become unambiguously stale; and
* work is attributed separately to comparison, rendering, lowering, graph
  validation, retirement, and native materialisation.

An ancestor render still enumerates its immediate output and the component
frontier it emits. Memoization does not make that enumeration free. Registry
indexing avoids global route scans, but immutable index updates can copy paths,
and an application's keyed getter can itself perform a linear collection
search. Scaling claims must account for each of those owners instead of
attributing every allocation or callback cost to rendering.

The scaling suite exercises full-root collections, local boundaries, text
density, tree depth, and tree breadth so the consequences of replacement scope
remain visible as the implementation evolves.

== Origin of the Action-State model

The Action-State model this platform implements originates with Richard
Feldman, who described it in
https://gist.githubusercontent.com/lukewilliamboswell/5c41387f4e3ee1d494d0c445616acffd/raw/4945dba566f9f27bd895c82765d038f2539dcfe2/gistfile1.txt[_Design Idea: Action-State_].
That write-up proposes a user interface API for Roc in which a renderer is a
pure function from state to an `Elem` value, event handlers return an `Action`
rather than a message, and a translation function relates a component's state to
its parent's state while marking the unit of re-rendering. roc-gui is an
development of that design. `Gui.update`, `Gui.none`, the shared `state`
type variable on `Elem` and `Action`, and adapting child renderers through
getters and setters follow its central idea: state ownership can identify the
subtree an action needs to update. Pure translations express that boundary;
explicit keys preserve logical identity through parent rebuilding, while the
host owns mounted lifetimes.

The motivation is worth restating, because it explains the shape of the API
more than any implementation detail does. A renderer takes state and returns a
description; it performs no effect, invokes no capability, and observes no clock, so
calling it twice with the same state yields the same description and calling it
is never a way to make something happen. Everything that can make something
happen is an `Action` returned from a handler, and an `Action` is a value: it
describes a transition rather than performing one. Constructing
`Gui.update(next)` changes nothing. The platform changes state only when it
receives that value back from a handler and accepts its graph transaction.

That division is what makes the concurrency tractable. Application state lives
on one thread, and every state transition is applied there, one at a time, by
the dispatcher installed for the currently mounted graph. Each turn takes the
state, runs one handler, applies the single action it returned, renders the
required scope, commits one graph decision, and installs its successor. Two transitions
cannot interleave, no handler can observe a half-applied update, and a handler
always receives the state that precedes it rather than a snapshot captured when
the tree was rendered. A handler's first argument is therefore the state to
build the next state from.

`Gui.task` extends the same discipline to work that must not block the
interface. It commits its `pending` state before handing the effect body
to a worker thread, which returns a reducer rather than a state value. The UI
thread applies that reducer to whatever the latest state is by then, so events
that arrived while the task was in flight are not overwritten by a stale
snapshot. The effect runs off the UI thread; the state transition it produces
still happens on the UI thread, in the same serialised order as every other
transition. Effects thus stay out of rendering entirely, and concurrency is
confined to the body of the work rather than spread through the state model.

Several ideas in the early write-up are useful independently of its proposed
surface syntax. Pure descriptions leave execution to the platform. Delegation
lets the parent decide whether to accept a child's proposal. Fallible state
projections make removal explicit. Deferred rendering enables memoized
subtrees. roc-gui gives those ideas one coherent ownership model through
pure translations, `Gui.delegate`, host-owned keyed lifetimes, and explicit
memo equivalence.

Periodic work uses `Gui.task` around a timer handle in application state,
with explicit cadence and cancellation. There is no string-keyed global effect
tracker. Instance liveness answers whether an owner still exists; application
request identity answers whether a result remains relevant to that live owner.
Those are distinct questions, and neither replaces the other.

== How this compares

[cols="1,2,2,2",options="header"]
|===
|Model |What persists |How application changes arrive |Identity on update

|roc-gui
|Mounted graph and GPUI entities outside rebuilt output and inside memo hits
|A state-derived subtree and explicit retained roots become one graph decision
|Scoped keyed component lifetimes; fresh ordinary IDs except in retained subtrees

|Virtual-tree reconciliation
|A native/render tree, often plus a previous description
|Old and new descriptions are diffed, commonly using keys
|The reconciler may preserve matching nodes

|Immediate mode
|Rendering-system state rather than an application widget tree
|Application code describes the interface repeatedly, commonly each frame
|Usually not expressed as persistent application widget identity

|Traditional retained widgets
|Application-visible widget objects
|Application code mutates long-lived widget properties and children
|Widget objects ordinarily retain identity until explicitly removed
|===

roc-gui combines a declarative Roc front end with retained native state. It is
not immediate mode because the application does not redraw the interface every
frame. It is not virtual-DOM reconciliation because render boundaries,
and declared memo equivalence, not a general tree diff, choose what survives. GPUI may perform its own internal
rendering invalidation; that is separate from roc-gui's application graph
replacement model.

== Semantic tests use the production graph

The semantic runner stops after the mounted-graph layer because it needs
no display server to locate semantic controls or assert text. It invokes the
real Roc renderer and dispatcher, consumes the real patches, and uses the same
`MountedGraph` implementation for validation, replacement, event routing, and
node accounting. It does not reproduce those behaviours in a test-only graph.

The interactive host continues by materialising GPUI entities. Consequently,
semantic specifications prove application behaviour and mounted topology, but do not
exercise `NodeView`, display frames, layout, paint, GPU work, or presentation.
Those require the interactive production path.

== Threading and observability

Application callbacks, graph commits, GPUI entity updates, and window work stay
on the interactive application path. Work owners maintain deterministic
component counts even when capture recording is disabled, so specifications
observe the same facts in both runners. Clock reads and capture records remain
behind recorder enablement.

With recording enabled, work owners emit bounded records. A separate writer
thread drains them in batches and commits transactions to the `.rgstats` SQLite
capture. UI behaviour never waits for a report query. If the recorder cannot
accept evidence, the capture records that loss rather than presenting partial
data as complete.

A timer means only the phase that owns it. Host application timing is not a
substitute for later layout, paint, GPU execution, or presentation. The
Understanding captures chapter covers availability and report views, and the
Measuring scaling chapter covers representative workloads.

== Correctness boundaries

The platform and host maintain these invariants across every event turn:

* one initial mount and one canonical mounted root;
* one completed action and graph decision per dispatch;
* unambiguous native identity for every live node;
* structurally valid changes applied only to mounted targets;
* stable logical projections and unique full-digest keys within each scope;
* retained subtrees keep their routes, descendants, and native identities;
* rebuilt routes advance their owner's revision; retired instances never revive;
* ancestor memo snapshots invalidated after descendant updates;
* completion owner liveness checked before captured state projections run;
* successor state, routes, and tasks published only after graph acceptance; and
* mounted-graph commit before GPUI materialisation.

A malformed ABI value or structurally invalid patch is a platform defect, not
application input to recover from. The host rejects it at the ownership
boundary rather than displaying a partially mutated graph.

Rows and columns stream their lowered child identities into nesting-safe,
host-owned builders. The closing node effect consumes its builder and stages
the same ordered graph node used everywhere else. This ownership boundary
avoids allocating a temporary Roc child-identity list and then copying it into
host storage. A patch cannot commit while a child builder remains unfinished,
and builders must close in nesting order.

A new feature crosses every owner it needs: public API, lowering and ABI, graph
representation and validation, GPUI behaviour, semantic locators and specifications,
scaling coverage, and documentation. The governing rule is one mounted graph,
one event route, and one production path: tests and measurements drive those
structures; they do not imitate them.
