= Building an application

== State, render, and actions

An application exports a state type and `main : Program(State)`:

[source,roc]
----
import pf.Action
import pf.Elem exposing [Elem]
import pf.Program exposing [Program]

State : { count : I64 }

render : State -> Elem(State)
render = |state| Elem.col({}, [
    Elem.text("Count: ${state.count.to_str()}"),
    Elem.button({
        label: Elem.text("Add one"),
        name: "Increment count",
        on_press: |previous, _event|
            Action.update({ count: previous.count + 1.I64 }),
    }),
])

main : Program(State)
main = Program.run({ init: { count: 0 }, render })
----

`render` is pure: it reads state and returns an `Elem(State)`. A button handler
receives the state associated with its render boundary and an `Event.Press`.
It returns one of three actions:

`Action.update(next_state)`:: Replace the boundary's state and render it again.
`Action.none`:: Keep the existing state and element tree unchanged.
`Action.task({ pending, run, resolve })`:: Commit `pending`, run `run` on the
bounded native worker pool, then invoke `resolve` against the latest state on
the UI thread.

Use `Action.none` when an event is valid but has no effect, such as pressing a
decrement button at a lower bound. It is both clearer and less work than
returning an unchanged state with `Action.update`.

== Timers and subscriptions

`Timer.start!({ interval_ms })` creates an opaque `Timer.Handle` for intervals
from 1 through 60,000 milliseconds. `Timer.next!(handle)` waits for one tick
and belongs inside `Action.task`; the next wait is started only after the
previous completion has been applied. This pull contract bounds backpressure
at one in-flight wait and does not accumulate missed ticks.

`Timer.cancel!(handle)` is idempotent, wakes an outstanding wait, and makes it
resolve as `Canceled`. Dropping the last typed `Box(U64)` handle also releases
the host registry entry. Applications retain the handle in state and decide
whether a `Fired` result schedules another wait.

== Elements and layout

`Elem.text(value)`:: Display a string.
`Elem.action_button(Elem.ActionButtonProps.{ ... })`:: Display a controlled,
styled action button. `caption` is visible text, `label` is its stable semantic
name, and `enabled` defaults to `True`. Enabled buttons participate in keyboard
tab order and activate with Enter or Space. Disabled buttons remain visible
with a subdued appearance and accept neither pointer nor keyboard activation.
Props include padding, sizing, growth, foreground and interaction colours,
border, radius, font size, and overflow.
`Elem.button({ label, name, on_press })`:: Concise text-button constructor over
the same native action-button node. Its `label` is a string; use
`Elem.action_button` for styling and explicit caption/semantic-label naming.
`Elem.checkbox(Elem.CheckboxProps.{ ... })`:: Display a semantic checkbox and handle
`Event.Check`. Props include enabled state, gap, padding, sizing, growth,
foreground and interaction colours, border, radius, font size, and overflow.
Enabled checkboxes participate in keyboard tab order and toggle with Space;
disabled checkboxes do not accept focus or activation.
`Elem.textarea(Elem.TextareaProps.{ ... })`:: Display a controlled multiline text
editor and handle `Event.Input`, which carries the complete requested value.
`label` is the stable semantic name; `placeholder`, `enabled`, and `read_only`
control editing behavior. A read-only textarea retains multiline layout and
scrolling for response and log views. Textareas share the native style fields
and default to a 160-logical-pixel editing viewport.
`Elem.image(Elem.ImageProps.{ label, bytes, format, ... })`:: Decode and render
capability-safe in-memory image bytes through GPUI. The explicit format is one
of `Png`, `Jpeg`, `Webp`, `Gif`, `Svg`, `Bmp`, or `Tiff`; fit defaults to
`Contain` and also supports `Cover`, `Fill`, `ScaleDown`, and `None`.
`grayscale` applies a native rendering effect. Image sources are values, never
ambient filesystem paths or URLs, and `label` is the stable semantic name.

`Elem.text_input(Elem.TextInputProps.{ ... })`:: Display a controlled,
single-line native editor. `label` is its stable semantic name, `value` is the
authoritative application value, and `placeholder` is shown only while empty.
Committed edits deliver the complete value in `Event.TextChange`; Enter delivers
`Event.TextSubmit`. The host retains focus, caret, selection, and an active IME
composition across controlled rerenders. Disabled fields accept neither edits
nor submission. Text values are bounded to one MiB of UTF-8.
Text-input labels are non-empty and unique in the mounted graph because they
also preserve the native editor entity across controlled rerenders.
`Elem.scroll(Elem.ScrollProps.{ name, content, axis })`:: Constrain content to
available space and scroll it vertically, horizontally, or in both directions.
The axis defaults to `Vertical`; `name` is the stable semantic identity.
`Elem.virtual_list(Elem.VirtualListProps.{ name, row_height, items })`:: Present
stable-keyed rows at one fixed logical height. Each item is an
`Elem.VirtualListItem.{ key, content }`; keys must be unique within the list.
The complete item graph remains available to semantic inspection and event
routing, while GPUI materializes only the current viewport range.
`Elem.row(Elem.RowProps.{ ... }, children)`:: Lay out children horizontally.
`Elem.col(Elem.ColProps.{ ... }, children)`:: Lay out children vertically.
`Elem.panel(Elem.PanelProps.{ ... }, children)`:: Group children vertically in
a labelled surface that is padded, bordered, and rounded by default.
`Elem.dialog(Elem.DialogProps.{ label, on_dismiss, ... }, children)`:: Present
one modal surface above an input-blocking scrim. The first enabled control gains
focus, Tab and Shift+Tab stay within the dialog, Escape calls `on_dismiss`, and
closing the dialog restores its opener by stable semantic identity. Render at
most one dialog at a time.

Row, column, panel, dialog, and action-button props share the native `Gui.Style` fields: gap, padding, width,
height, growth, colours, borders, radius, font size, and per-axis overflow.
`Auto`, `Fill`, and `Px(n)` express dimensions. An optional non-empty `label`
provides a stable semantic locator, such as
`(role panel :name "Directory view")`; it does not add visible text.

Rows and columns accept a `List(Elem(State))`, which makes ordinary list
transformations useful for repeated UI:

[source,roc]
----
render_names : List(Str) -> Elem(State)
render_names = |names| Elem.col(
    Elem.ColProps.{ width: Fill, gap: 6 },
    names.map(|name| Elem.text(name)),
)
----

The empty `{}` retains neutral defaults. Semantic element names are not visible
labels. Give each simultaneously visible button a
unique, stable name such as `"Delete row ${row.id.to_str()}"`; specifications
use that identity instead of screen position.

Keyboard focus has a visible outline. Tab and Shift+Tab traverse enabled
buttons, checkboxes, and text inputs in rendered child order, so application
layout order is also the default keyboard order. Keep labels concise and
semantic names stable across state updates.

`Program.run` also accepts a `window` record with an initial logical `width`,
`height`, and titlebar `title`. Defaults preserve the compact two-field form;
windows remain resizable and layout elements using `Fill` follow the available
viewport.

== Local state with `Elem.translate`

A large application often contains parts that can update independently.
`Elem.translate` adapts an element whose handlers work with child state into an
element that participates in a parent application:

[source,roc]
----
State : { title : Str, counter : Counter.State }

render : State -> Elem(State)
render = |state| Elem.col({}, [
    Elem.text(state.title),
    Elem.translate(
        |child| Counter.render("Main", child),
        |parent| parent.counter,
        |parent, child| { ..parent, counter: child },
    ),
])
----

Its arguments are:

. a renderer for the child state;
. a getter that extracts child state from parent state;
. a setter that returns parent state with the child replaced.

Translation is also a render boundary. A button inside the counter receives
`Counter.State`; when it updates, the platform writes that child back into the
parent and replaces the counter subtree. The title and other sibling subtrees
are not rebuilt.

Use a boundary around a component that owns a coherent slice of state and
changes independently. Do not add boundaries merely to group layout; use rows
and columns for visual grouping.

See <<_boundaries_determine_update_scope>> for what is retained and replaced,
and why this is a boundary operation rather than a virtual-tree diff.

For a complete reusable component, see `examples/counter/Counter.roc` and its
composition in `examples/counter/main.roc`.

== Directory capabilities and tasks

`Files.pick_directory!({})` acquires the read-only directory capability granted
by `--host-cap-dir PATH`. With no grant it returns
`PickDirectoryErr(AccessDenied)`. The returned
`Files.Dir.Read` is an opaque, reference-counted handle: it may be stored in
state or captured by tasks, but applications cannot forge it or recover an
ambient path. Internally it uses the platform-wide typed `Resource.Handle`
representation, leaving the same ABI shape available to future resource APIs.

`Files.Dir.list!(directory)` lists at most 10,000 direct children and 4 MiB of
UTF-8 names. Entries distinguish files, directories, symlinks, and other file
types. `Files.Dir.open_read_dir!(directory, name)` acquires a direct child
directory without following the final symlink; names containing traversal or
multiple path components are rejected. `Files.Dir.read!(directory, name)` reads
one direct ordinary file as a bounded `List(U8)` without following links. The
64 MiB bound returns `ResourceLimit` instead of constructing an unbounded
application value. Run filesystem operations inside
`Action.task`, as shown by `examples/folder-browser/main.roc`.

Filesystem failures use the `Files.FileErr` tag union. Its
`ListDirectoryErr`, `OpenReadDirectoryErr`, `PickDirectoryErr`, and
`ReadFileErr` tags identify the failed operation directly; each carries a
portable `Files.Reason` value.

Retain a root-to-current list of directory handles to implement Back and
clickable breadcrumbs without exposing paths. Relist a retained handle before
committing navigation, and attach a monotonically increasing request identity
to asynchronous work so a superseded completion cannot replace a newer view.

== Process and pseudo-terminal capabilities

`Process.acquire!` returns an opaque process grant only when the application is
launched with `--host-cap-process=local-shell` or
`--host-cap-process=test-program`. The grant fixes the only profile that may be
started. `Process.spawn!` accepts only the grant and terminal dimensions;
applications never provide a profile, executable path, arguments, environment
variables, or command lines to the host.

`Process.spawn!` creates a real pseudo-terminal with an explicitly bounded row
and column size. `Process.read!`, `Process.write!`, `Process.resize!`, and
`Process.cancel!` require its typed `Process.Pty` handle. Reads and writes are
capped at 65,536 bytes per call, one read may wait on a PTY, and cancellation
wakes that wait. Blocking operations belong in `Action.task`, whose completion
is reconciled with the latest state on the ordinary event route.

Failures carry their operation in the tag, such as
`SpawnProcessErr(AccessDenied)` or `ReadProcessErr(Busy)`. Process grants and
PTYs are opaque `Box(U64)` resources and cannot be confused with other handle
kinds.

== HID device capabilities

`Device.acquire!` returns an opaque grant only when the host has authorized one
exact virtual device or physical USB vendor/product identity. Applications
cannot request arbitrary hardware, inspect operating-system device paths, or
read serial numbers. `Device.discover!` lists only comparison-safe identity
within that grant, and `Device.connect!` connects exactly the granted device.

Connections are typed `Box(U64)` resources. `Device.transact!` exchanges one
bounded byte request and response; device-specific framing and values belong in
an application or protocol package rather than the platform. Physical HID and
deterministic virtual transports enter this same operation. Blocking discovery,
connection, and transactions run through `Action.task`.

Failures retain their operation in tags such as
`DiscoverDeviceErr(NotFound)` and `TransactDeviceErr(Protocol)`. Connection and
transaction lifecycle counts are recorded by the host that owns those events.

== Durable application data

`Files.app_data!({})` acquires the application's private read-write directory
granted by `--host-cap-app-data PATH`. The result is an opaque typed
`Files.Dir.ReadWrite` handle; applications cannot recover the host path.

`Files.Dir.read_utf8!(directory, name)` distinguishes `Missing` from
`Value(Str)`. `Files.Dir.write_utf8_atomic!(directory, name, value)`
synchronizes a private temporary file before replacing the direct child in the
same directory. Names are flat ASCII identifiers of at most 128 bytes, values
are UTF-8 of at most one MiB, and the ordinary operation-tagged `Files.FileErr`
surface reports acquisition, read, and write failures.

Run these blocking operations inside `Action.task`, with a monotonic request
identity when an edit can supersede pending work. The Settings Center uses this
route and retains a newer draft when an older load completes.

== Audio output capabilities

`Audio.acquire!({})` acquires an opaque output handle only when the host was
launched with `--host-cap-audio`. `Audio.load!(output, directory, name)` loads
one direct file through an existing `Files.Dir.Read` grant; names with traversal
or multiple components are rejected and encoded input is bounded to 64 MiB.
The host delegates media decoding and playback to Rodio and Symphonia.

`Audio.Track` is an opaque host resource. `Audio.play!`, `Audio.pause!`,
`Audio.seek!`, `Audio.status!`, and `Audio.stop!` are bounded operations intended
for `Action.task`. Status reports the decoder-owned duration, playback position,
and `Playing`, `Paused`, or `Stopped` state. `Audio.AudioErr` identifies
the failed operation and carries a portable reason such as `DecodeFailed`,
`OutputUnavailable`, or `InvalidCapability`.

Specification runs may receive a harness-owned null-output grant. It drains
the same paced Rodio mixer, decoder, and player state used by a system output;
it changes only the final device sink.

== Clipboard capabilities

`Clipboard.acquire!({})` acquires text clipboard authority only when the host
was launched with `--host-cap-clipboard`. Its opaque `Clipboard.Handle` uses
the common typed `Box(U64)` representation and cannot be manufactured or
confused with another resource family.

`Clipboard.read_text!(handle)` returns a bounded UTF-8 snapshot with a
monotonic sequence. Applications compare sequences to suppress stale reads and
deduplicate repeated content. `Clipboard.write_text!(handle, text)` schedules
replacement on GPUI's owning UI context. Both directions reject values larger
than 64 KiB. `Clipboard.ClipboardErr` identifies acquisition, reading, and
writing with distinct operation tags carrying a portable reason.

Observe changes with one pull-based `Timer` subscription inside `Action.task`.
Pause by cancelling that timer; sensitive values are discarded before they
enter state. Clipboard content is application data and never enters host
diagnostics or observatory captures.

== HTTP requests

Applications declare `roc-lang/http` v1.0.0 and build its canonical `Request`
values. `Http.acquire!({})` returns an opaque `Http.Client` only when the host
was launched with `--host-cap-http-origin ORIGIN`. The grant names one exact
scheme, host, and effective port; requests and redirects cannot leave it.

`Http.send!(client, config, request)` performs one bounded exchange and returns
the package's canonical `Response`. Call it from `Action.task` so connection,
TLS, and response work runs on the native worker pool and its reducer returns
through the ordinary UI-thread completion dispatcher.

Requests and config make policy explicit: method, URI, headers, body, timeout,
`max_response_bytes`, and `max_redirects`. URLs must use `http` or `https`.
The platform accepts standard methods, at most 64 headers and 32 KiB of header
data, a request body up to 1 MiB, a timeout from 1 through 60,000 milliseconds,
a response limit from 1 byte through 4 MiB, and from zero through ten redirects.
Response bodies remain `List(U8)` so downstream packages share the same nominal
types. Portable failures distinguish invalid inputs, denied or invalid
capabilities, unsupported schemes, connection and timeout failures, and
redirect and body limits.

Give each submitted request a monotonically increasing identity. In the task
resolver, compare that identity with the latest state and return `Action.none`
for an obsolete result. This prevents a slow earlier response from replacing a
newer response without creating a second completion route.

== Read-only SQLite capabilities

`Sqlite.open_read!(directory, name)` opens one direct ordinary child of a
granted directory as a read-only database capability. The operation rejects
path traversal and symlinks and never exposes an ambient path. Database bytes
are bounded to 64 MiB and the returned `Sqlite.Read` is an opaque, reference-
counted `Box(U64)` handle whose final release closes the native connection.

`Sqlite.query!(database, sql)` prepares and executes one read-only statement.
Results preserve SQLite's `Null`, `Integer`, `Real`, `String`, and `Bytes`
value kinds. Queries are bounded to 64 KiB of SQL, 256 columns, 10,000 rows,
and 16 MiB of returned text and blob bytes. Limit violations and invalid,
corrupt, busy, inaccessible, or non-database resources are typed errors.
Failures use `OpenDatabaseErr(reason)` and `QueryDatabaseErr(reason)`, so callers
can distinguish the failed operation before matching the portable reason.
Every reason retains SQLite's bounded diagnostic string; `Sqlite.detail`
extracts it for user-facing status without flattening the public error type.

Open and query calls are blocking capability operations. Run them inside
`Action.task`, retain the last successful view while work is pending, and use a
monotonic request identity in the resolver so an older completion cannot
replace a newer result. `examples/database-browser` demonstrates this pattern.

== TCP endpoint capabilities

`Tcp.connect!({})` opens an ordered byte stream to the single numeric
`IP:PORT` endpoint granted with `--host-cap-tcp`. Without that host grant it
returns `ConnectErr(AccessDenied)`. The application cannot select or derive a
different destination from the opaque handle, and releasing its final
reference closes the socket and removes the host registry entry.

`Tcp.Stream.read_up_to!(stream, max_bytes)` reads between one byte and a
one-MiB requested maximum; an empty list means orderly end of stream.
`Tcp.Stream.write_all!(stream, bytes)` writes the complete value or fails and
accepts at most 16 MiB. `Tcp.Stream.close!(stream)` is idempotent. Connections,
reads, and writes have finite native timeouts, and failures use the
operation-tagged `Tcp.TcpErr` union: `ConnectErr`, `ReadErr`, `WriteErr`, or
`CloseErr` wraps a portable reason.

TCP operations block and belong inside `Action.task`. Protocol packages build
on the byte transport rather than being reimplemented by the platform. The
Redis Explorer adapts a stream with `roc-redis`'s `Transport.from_bytes_io`, so
command encoding, bounded RESP2 decoding, typed commands, and exchange policy
remain the responsibility of the established platform-independent package.
== Retained canvas

`Elem.canvas` paints an ordered list of keyed `Rectangle`, `Ellipse`, and
`Line` primitives in native GPUI. A canvas and every primitive have stable
semantic labels. Primitive keys are non-zero and unique within the canvas;
they preserve direct-manipulation identity independently of list position.

The controlled `on_pointer` handler receives `Begin`, `Move`, and `End` in
integer canvas coordinates. The topmost hit-tested primitive is captured on
`Begin`, and that same optional target key accompanies the complete gesture,
including when a state update replaces the canvas subtree.
