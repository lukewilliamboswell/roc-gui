# Security policy

Report a vulnerability privately with GitHub's **Security → Report a
vulnerability** for this repository. Do not put credentials, exploit details, or
private data in a public issue. Ordinary bugs belong in the issue tracker.

Include the affected release or commit, the impact, steps to reproduce, and
relevant logs with credentials removed. The maintainer assesses the report and
coordinates the fix and its disclosure through the private report, aiming to
respond within 14 days.

Fixes land in the next platform release. Applications pinned to an older
release's bundle URL receive a fix by moving to that release; published
releases are immutable and are not patched in place. Release notes name any
assigned vulnerability identifier.

Every release asset carries a build-provenance attestation, and each release's
[notes](docs/releases.adoc) say how to verify what you downloaded.
